## 📋 Пункт 1. Выбрать источник данных

Студент выбирает **один** источник из списка и обосновывает выбор в `README.md`: что за данные, схема, объём, почему этот источник.

**Примеры источников:**
1. Локальный файл (готовый или сгенерированный датасет) — CSV/JSON/Parquet в `data/`
2. Несколько локальных файлов — папка с 5–10 файлами
3. Excel (`.xlsx`)
4. Генератор (Faker)
5. Файл в S3 (MinIO)
6. БД (Postgres / Clickhouse)
7. Веб-скрапинг (статический HTML, например Wikipedia)
8. REST API
9. FTP / SFTP-сервер (в Docker)
10. RabbitMQ (очередь сообщений)
11. Kafka (продюсер + консьюмер)

**Что должно быть в `README.md` по пункту 1:**
- Название источника и его тип.
- Что за данные (схема: поля, типы, пример строки).
- Объём (сколько строк/событий).
- Почему выбран именно этот источник (1–2 предложения).
- Ссылка на источник (если API — URL, если файл — путь в репозитории).

**Критерии оценки (макс. 2 балла):**

| Балл | Что сделано |
| :--- | :--- |
| **2** | Источник выбран, обоснован в README, описаны схема данных и объём. Если API — указан endpoint и пример ответа. |
| **1.5** | Источник выбран и работает, но README неполный (нет схемы или объёма). |
| **1** | Источник выбран, но нет обоснования и описания. |
| **0.5** | Источник выбран формально, данные не описаны, но код работает. |
| **0** | Источник не выбран или не работает. |

## 🐳 Пункт 2. Развернуть инструменты в Docker

Студент поднимает **целевую БД** и, если нужно, **источник** через `docker-compose.yml`. Минимум — одна целевая БД. Если источник требует инфраструктуры (S3, Kafka, FTP, RabbitMQ), она тоже поднимается в том же `docker-compose.yml`.

**Примеры целевых БД:**
1. Postgres
2. ClickHouse
3. S3 (MinIO)
4. SQLite / MySQL / MariaDB
5. DuckDB
6. MongoDB
7. Redis

**Требования к `docker-compose.yml`:**
- Фиксированные версии образов (`postgres:15`, не `latest`).
- `healthcheck` для целевой БД.
- `volumes` для персистентности.
- Порты на localhost.
- Пароли через `.env`, `.gitignore` исключает `.env`, `.venv/`, `__pycache__/`, `data/`.
- `init/init.sql` создаёт схему и целевую таблицу.

**Критерии оценки (макс. 3 балла):**

| Балл | Что сделано |
| :--- | :--- |
| **3** | `docker compose up -d` работает с нуля. Фиксированные версии, healthcheck, volumes, `.env`, `init.sql` создаёт схему и таблицу. README содержит команды запуска. |
| **2.5** | Всё работает, но нет healthcheck или volumes. |
| **2** | Работает, но версии `latest` или пароли в коде. |
| **1.5** | Стек поднимается, но `init.sql` не создаёт таблицу — приходится создавать вручную. |
| **1** | Поднята только целевая БД, хотя источник требует инфраструктуры (S3, Kafka, FTP). |
| **0.5** | `docker-compose.yml` есть, но `docker compose up -d` падает. |
| **0** | Инфраструктура не поднята. |

## 📓 Пункт 3. Jupyter Notebook: Extract → Transform → Load

Ноутбук `notebooks/etl.ipynb` запускается **сверху вниз без ручных правок**.

**Обязательные ячейки:**
1. Markdown «Описание»: что делает ноутбук, источник, целевая таблица.
2. «Импорты»: `pandas`, `boto3`, `psycopg2`, `requests`, `kafka-python` — по источнику.
3. «Конфигурация»: чтение `.env` через `python-dotenv`, параметры подключения.
4. «Extract»: извлечение данных (пагинация для API, консьюмер для Kafka и т.д.).
5. «Transform»: приведение типов, переименование колонок, отбрасывание мусора (при необходимости).
6. «Load»: запись в целевую БД.
7. «Проверка»: `SELECT COUNT(*)` + первые 5 строк.

**Требования к ноутбуку:**
- **Идемпотентность:** повторный запуск не создаёт дубли (`ON CONFLICT DO NOTHING` или `TRUNCATE + INSERT`).
- **Обработка ошибок:** `try/except` вокруг подключений, понятные сообщения.
- **Параметры через `.env`:** пароли не хардкодятся.
- **Читаемость:** осмысленные имена переменных, комментарии к неочевидным местам.

**Критерии оценки (макс. 4 балла):**

| Балл | Что сделано |
| :--- | :--- |
| **4** | Ноутбук запускается сверху вниз. Extract, Transform, Load — все три стадии осмысленны. Идемпотентность. Обработка ошибок. Параметры через `.env`. README с инструкцией и скриншотом. |
| **3.5** | Всё работает, но идемпотентность не реализована (повторный запуск создаёт дубли). |
| **3** | Работает, но нет обработки ошибок или пароли захардкожены. |
| **2** | Extract и Load есть, но код нечитаемый или не воспроизводится с первого запуска. |
| **1.5** | Ноутбук работает частично (например, Extract есть, Load падает). |
| **1** | Ноутбук есть, но не запускается. |
| **0** | Ноутбука нет или он пустой. |
